01. 재무제표와 전표 데이터 구조

재무제표 금액이 어떤 전표·원장·보조원장에서 만들어지는지 추적하고, 일반감사의 증빙 대조 방식과 전산감사의 데이터 계보 추적 방식을 나란히 실습합니다.

실습 시나리오

12월 말 결산법인의 매출채권과 매출액이 전년 대비 크게 증가했습니다. 감사인은 재무제표 숫자를 단순히 확인하는 데서 끝나지 않고, 재무제표 → 총계정원장 → 전표 → 거래처원장 → 세금계산서·입금내역으로 이어지는 연결 관계를 설명해야 합니다.

핵심 감사위험: 재무제표 금액이 수기로 조정되었거나, 전표가 총계정원장에 반영되는 과정에서 누락·중복·기간오류가 발생했을 가능성입니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 확인, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 재무상태표와 손익계산서의 해당 계정 금액을 표시하고 전년 대비 증감률을 계산합니다.
  • 감사조서에는 매출채권·매출액 잔액표, 거래처별 보조원장, 주요 전표 사본, 세금계산서, 입금증을 순서대로 첨부합니다.
  • 금액이 큰 거래처 5개를 선정하여 전표 번호, 거래일자, 공급가액, 부가세, 입금일자를 수기로 대조합니다.
  • 재무제표 금액과 원장 금액이 일치하지 않으면 회사 담당자에게 조정분개 내역과 사유서를 요청합니다.
  • 수강생은 표본 거래 3건에 대해 일반감사 조서의 색인, 절차, 결론 문구를 직접 작성합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 바꾸어 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • ERP에서 전표 헤더, 전표 라인, 계정마스터, 거래처마스터, 세금계산서 테이블을 CSV로 추출합니다.
  • 전표번호·회계연도·회사코드를 키로 설정하여 재무제표 계정 잔액이 어떤 전표 라인에서 집계되는지 매핑합니다.
  • 전표 라인의 차변·대변 합계가 0인지, 승인 상태가 미승인인데 원장에 반영된 건이 있는지 전체 모집단을 검사합니다.
  • 월별·사용자별·계정별 집계 피벗을 만들고 비정상적인 대량 입력, 휴일 입력, 마감 이후 입력을 표시합니다.
  • 수강생은 전표 데이터 계보표와 예외 거래 리스트를 만들고 일반감사 조서와 연결합니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
대상 범위일반감사는 금액이 큰 표본과 증빙 위주로 확인합니다.전산감사는 전체 전표 모집단과 테이블 간 연결성을 먼저 확인합니다.
증거 형태PDF 증빙, 원장 출력물, 담당자 확인 메모가 중심입니다.CSV 원천 데이터, 조인 결과, 예외 쿼리, 로그 파일이 증거가 됩니다.
결론 방식선정 표본에서 큰 오류가 없으면 합리적 결론을 냅니다.데이터 완전성과 처리 로직을 확인한 뒤 예외 거래를 일반감사 절차로 재확인합니다.

실습 데이터 예시

수업에서는 아래와 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 만들고, 일부 오류를 의도적으로 심어 비교 실습을 진행합니다.

  • GL_BALANCE: account_code, fiscal_year, period, debit, credit, ending_balance
  • JE_HEADER: company_code, journal_id, posting_date, input_user, approval_status
  • JE_LINE: journal_id, line_no, account_code, customer_id, debit_amount, credit_amount

수업 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 만들고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 확인 결과와 데이터 분석 결과가 서로 맞는지 확인한 뒤 최종 발견사항을 정리합니다.
