06-07. 인터페이스·배치 데이터 대사

시스템 간 데이터 이동 과정의 누락과 중복을 점검합니다. 이 과정은 실제 감사 현장에서 바로 설명할 수 있는 문제정의, 증거 수집, 예외 판단, 결론 작성까지 하나의 흐름으로 실습합니다.

실습 시나리오

쇼핑몰 주문 데이터가 ERP 매출 전표로 넘어오는 과정에서 일부 주문은 누락되고 일부 주문은 두 번 반영되었습니다. 학습자는 원천 주문, 인터페이스 큐, ERP 전표를 연결해 전송 완전성을 검토합니다.

핵심 감사위험: 인터페이스 통제가 약하면 업무 담당자는 화면상 정상 처리로 인식하지만 회계 데이터에는 누락·중복이 남을 수 있습니다.

분석 설계 실습

CISA식 전산감사 관점에서 필요한 판단과 증거를 먼저 정의합니다. 단순 체크리스트가 아니라 왜 이 절차가 필요한지, 어떤 결론에 쓰이는지를 함께 작성합니다.

  • 원천·중간·대상 테이블 키 정의
  • 배치 실행 결과와 오류 로그 분석
  • 전송 건수와 금액 대사
  • 재처리 건의 중복 반영 여부 확인
  • 인터페이스 통제 개선안 작성

감사 활용 실습

회계 데이터 분석 적용으로 연결하여 수업 산출물이 실제 감사조서, 개선권고, 포트폴리오 설명 자료로 이어지도록 만듭니다.

  • 인터페이스·배치 데이터 대사와 관련된 원천 데이터 또는 증거 위치를 식별합니다.
  • 정상 처리와 예외 처리를 구분하는 판단 기준을 작성합니다.
  • 검토 결과를 위험도, 영향도, 추가 확인 필요 항목으로 분류합니다.
  • 담당자 인터뷰 질문과 요청 증빙 목록을 만듭니다.
  • 최종 결론 문구와 개선 권고안을 작성합니다.

비교 포인트

구분CISA식 전산감사 관점회계 데이터 분석 적용
출발점위험, 통제목적, 감사증거의 신뢰성을 먼저 정의합니다.데이터, 로그, 증빙, 산출물로 검증 가능한 절차를 설계합니다.
검토 방식인터뷰, 문서검토, 설정 확인, 표본 검토로 통제 수행 여부를 확인합니다.전체 모집단 분석, 예외 추출, 재수행 테스트, 결과 대사를 수행합니다.
최종 산출물감사 판단과 미비점 근거를 조서화합니다.반복 가능한 분석 파일, 예외 리스트, 개선 권고안으로 연결합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실무 자료와 유사한 구조로 만들되 개인정보와 회사 고유정보는 모두 제거한 가상 데이터로 구성합니다.

  • ORDER_SRC: order_id, order_date, gross_amount, status
  • IF_QUEUE: interface_id, source_key, sent_at, result_code
  • ERP_JOURNAL_LINK: source_key, journal_id, posted_amount

교육 진행 흐름

  1. 1단계: 감사위험을 읽고 필요한 데이터 원천을 표시합니다.
  2. 2단계: 원천 데이터의 완전성과 정확성을 먼저 확인합니다.
  3. 3단계: SQL 또는 분석 규칙으로 전체 모집단 예외를 추출합니다.
  4. 4단계: 예외를 증빙 검토 결과와 연결해 실제 오류와 정상 예외를 구분합니다.
  5. 5단계: 분석 조건, 한계, 결론을 조서 형태로 정리합니다.

교육 산출물

  • 데이터 요청목록과 원천 검증표
  • 예외 추출 규칙과 분석 결과표
  • 감사조서용 결론 메모
  • 재수행 가능한 쿼리·코드 파일
