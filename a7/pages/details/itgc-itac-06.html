05-06. 자동계산 통제 테스트

시스템 계산 로직을 독립적으로 재수행해 정확성을 검증합니다.

실습 시나리오

ERP가 매출 할인, 부가세, 감가상각, 충당금 계산을 자동 수행하지만 일부 거래에서 반올림 규칙과 기준일 적용이 다릅니다. 학습자는 계산 로직을 재수행해 차이를 식별합니다.

핵심 감사위험: 자동계산 통제 오류는 표본 몇 건의 오류가 아니라 전체 모집단에 반복적으로 영향을 줄 수 있어 재무제표 왜곡 규모가 커질 수 있습니다.

과정 구분: ITAC

계산 로직 이해 실습

업무 규정과 시스템 로직이 일치하는지 확인하고 재수행 기준을 수립합니다.

  • 계산 대상 거래, 기준 금액, 적용률, 기준일, 반올림 규칙을 정의합니다.
  • 업무 규정서와 시스템 설정 화면의 값이 일치하는지 비교합니다.
  • 예외 조건, 수동 조정, override 허용 여부를 확인합니다.
  • 계산 통제의 재무제표 주장과 관련 계정을 연결합니다.
  • 재수행 결과 차이에 대한 허용오차 기준을 설정합니다.

재수행 테스트 실습

원천 데이터를 이용해 계산값을 독립적으로 산출하고 시스템 결과와 비교합니다.

  • 원천 거래 데이터에서 재수행에 필요한 필드를 추출합니다.
  • 계산식을 엑셀 또는 SQL로 구현해 기대값을 산출합니다.
  • 시스템 계산값과 기대값의 차이를 금액·비율 기준으로 분석합니다.
  • 차이 발생 건을 로직 오류, 설정 오류, 정상 예외로 분류합니다.
  • 오류가 모집단 전체에 미치는 잠재 영향을 추정합니다.

감사 접근 비교 포인트

구분통제 설계 검토데이터 기반 운영평가
감사 초점계산 로직 이해 실습에서 통제 설계와 책임 구조를 확인합니다.재수행 테스트 실습에서 데이터와 시스템 결과로 운영 여부를 입증합니다.
증거 방식정책서, 승인 문서, 인터뷰, 화면 증거를 활용합니다.원천 테이블, 로그, 변경 이력, 재수행 결과를 활용합니다.
결론 연결통제 미비의 원인과 보완통제 필요성을 정리합니다.예외 건수, 금액 영향, 반복 가능 감사절차를 산출합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실제 ERP와 감사조서 구조를 단순화하여 구성하고, 일부 오류를 의도적으로 반영합니다.

  • CALC_INPUT: transaction_id, base_amount, rate_code, effective_date, condition_type
  • CALC_OUTPUT: transaction_id, system_amount, calculated_at, override_flag
  • RATE_MASTER: rate_code, rate_value, valid_from, valid_to, rounding_rule

교육 진행 흐름

  1. 통제 이해: 업무 프로세스와 시스템 흐름을 읽고 통제 목적을 표시합니다.
  2. 위험 식별: 오류가 발생할 수 있는 입력, 처리, 출력, 변경 지점을 정리합니다.
  3. 증거 설계: 필요한 정책서, 화면, 로그, 테이블, 승인 증적을 정의합니다.
  4. 테스트 수행: 설계평가와 운영평가 절차를 수행하고 예외를 분류합니다.
  5. 결론 작성: 재무제표 영향, 통제 영향, 개선권고를 감사조서 문구로 작성합니다.
