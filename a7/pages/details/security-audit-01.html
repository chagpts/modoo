07-01. 회계 시스템 보안 위협 모델링

회계 데이터 왜곡으로 이어지는 보안 위협을 구조화합니다. 이 과정은 실제 감사 현장에서 바로 설명할 수 있는 문제정의, 증거 수집, 예외 판단, 결론 작성까지 하나의 흐름으로 실습합니다.

실습 시나리오

ERP, 전자세금계산서, 결재시스템, 파일서버가 연결된 환경에서 계정 탈취와 권한 오남용이 발생했습니다. 학습자는 정보보안기사의 시스템보안·관리보안 관점을 회계감사 위험으로 연결합니다.

핵심 감사위험: 기밀성 침해만 보는 것이 아니라 무결성 훼손이 재무제표 오류로 이어지는 경로를 식별해야 합니다.

보안 점검 실습

정보보안기사식 보안 점검 관점에서 필요한 판단과 증거를 먼저 정의합니다. 단순 체크리스트가 아니라 왜 이 절차가 필요한지, 어떤 결론에 쓰이는지를 함께 작성합니다.

  • 자산·위협·취약점·영향 분류
  • 회계 데이터 무결성 훼손 시나리오 작성
  • 중요 시스템과 중요 계정 매핑
  • 보안 통제와 회계 통제 연결
  • 우선 점검 대상 선정

회계 시스템 영향 분석

회계 시스템 감사 적용으로 연결하여 수업 산출물이 실제 감사조서, 개선권고, 포트폴리오 설명 자료로 이어지도록 만듭니다.

  • 회계 시스템 보안 위협 모델링와 관련된 원천 데이터 또는 증거 위치를 식별합니다.
  • 정상 처리와 예외 처리를 구분하는 판단 기준을 작성합니다.
  • 검토 결과를 위험도, 영향도, 추가 확인 필요 항목으로 분류합니다.
  • 담당자 인터뷰 질문과 요청 증빙 목록을 만듭니다.
  • 최종 결론 문구와 개선 권고안을 작성합니다.

비교 포인트

구분정보보안기사식 보안 점검 관점회계 시스템 감사 적용
출발점위험, 통제목적, 감사증거의 신뢰성을 먼저 정의합니다.데이터, 로그, 증빙, 산출물로 검증 가능한 절차를 설계합니다.
검토 방식인터뷰, 문서검토, 설정 확인, 표본 검토로 통제 수행 여부를 확인합니다.전체 모집단 분석, 예외 추출, 재수행 테스트, 결과 대사를 수행합니다.
최종 산출물감사 판단과 미비점 근거를 조서화합니다.반복 가능한 분석 파일, 예외 리스트, 개선 권고안으로 연결합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실무 자료와 유사한 구조로 만들되 개인정보와 회사 고유정보는 모두 제거한 가상 데이터로 구성합니다.

  • ASSET_LIST: asset_id, system_name, data_type, owner
  • THREAT_SCENARIO: threat_id, attack_path, accounting_impact
  • CONTROL_MAP: security_control, accounting_assertion, evidence

교육 진행 흐름

  1. 1단계: 회계 시스템 자산과 보안 위협을 식별합니다.
  2. 2단계: 설정값, 로그, 권한, 취약점 증거를 수집합니다.
  3. 3단계: 기술 취약점이 회계 데이터에 미치는 영향을 평가합니다.
  4. 4단계: 개선조치와 재테스트 기준을 작성합니다.
  5. 5단계: 감사보고용 발견사항으로 정리합니다.

교육 산출물

  • 보안 점검 체크리스트
  • 회계 시스템 영향도 평가표
  • 취약점별 개선 권고안
  • 재테스트 증거 목록
