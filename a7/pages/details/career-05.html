09-05. GitHub와 문서 저장소 구성

포트폴리오 저장소를 읽기 쉽게 구성합니다. 이 과정은 실제 감사 현장에서 바로 설명할 수 있는 문제정의, 증거 수집, 예외 판단, 결론 작성까지 하나의 흐름으로 실습합니다.

실습 시나리오

학습자는 공개용 GitHub 또는 문서 저장소에 프로젝트별 폴더를 만들고 README, 샘플 데이터, 분석 코드, 결과 이미지를 정리합니다. 민감정보 제거와 라이선스 표시도 함께 점검합니다.

핵심 감사위험: 저장소 구조가 복잡하면 평가자가 핵심 역량을 보기 어렵습니다.

포트폴리오 설계 실습

커리어 설계 관점에서 필요한 판단과 증거를 먼저 정의합니다. 단순 체크리스트가 아니라 왜 이 절차가 필요한지, 어떤 결론에 쓰이는지를 함께 작성합니다.

  • 프로젝트별 폴더 구조 설계
  • README 첫 화면 메시지 작성
  • 샘플 데이터와 결과 파일 분리
  • 실행 방법과 환경 정보 작성
  • 민감정보 제거 체크리스트 적용

커리어 전환 실습

포트폴리오 산출물 적용으로 연결하여 수업 산출물이 실제 감사조서, 개선권고, 포트폴리오 설명 자료로 이어지도록 만듭니다.

  • GitHub와 문서 저장소 구성와 관련된 원천 데이터 또는 증거 위치를 식별합니다.
  • 정상 처리와 예외 처리를 구분하는 판단 기준을 작성합니다.
  • 검토 결과를 위험도, 영향도, 추가 확인 필요 항목으로 분류합니다.
  • 담당자 인터뷰 질문과 요청 증빙 목록을 만듭니다.
  • 최종 결론 문구와 개선 권고안을 작성합니다.

비교 포인트

구분커리어 설계 관점포트폴리오 산출물 적용
출발점위험, 통제목적, 감사증거의 신뢰성을 먼저 정의합니다.데이터, 로그, 증빙, 산출물로 검증 가능한 절차를 설계합니다.
검토 방식인터뷰, 문서검토, 설정 확인, 표본 검토로 통제 수행 여부를 확인합니다.전체 모집단 분석, 예외 추출, 재수행 테스트, 결과 대사를 수행합니다.
최종 산출물감사 판단과 미비점 근거를 조서화합니다.반복 가능한 분석 파일, 예외 리스트, 개선 권고안으로 연결합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실무 자료와 유사한 구조로 만들되 개인정보와 회사 고유정보는 모두 제거한 가상 데이터로 구성합니다.

  • REPO_TREE: folder, purpose, included_files
  • RUN_GUIDE: step, command, expected_output
  • PRIVACY_CHECK: item, risk, treatment

교육 진행 흐름

  1. 1단계: 목표 직무와 보여줄 역량을 선택합니다.
  2. 2단계: 수업 산출물을 프로젝트 단위로 재구성합니다.
  3. 3단계: 공개 가능한 데이터와 설명 자료로 정리합니다.
  4. 4단계: README, 발표자료, 이력서 문장으로 전환합니다.
  5. 5단계: 피드백을 반영해 제출 가능한 포트폴리오로 완성합니다.

교육 산출물

  • 프로젝트 README 초안
  • 포트폴리오 목차와 링크 구조
  • 면접 설명 스크립트
  • 개선 피드백 반영표
