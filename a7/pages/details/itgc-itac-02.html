05-02. 접근권한 통제

ITAC 신뢰성의 전제가 되는 사용자 권한과 SoD 위험을 점검합니다.

실습 시나리오

ERP 사용자 중 퇴사자 계정이 비활성화되지 않았고, 일부 사용자는 전표 입력과 승인 권한을 동시에 보유하고 있습니다. 학습자는 권한 마스터와 사용자 로그를 활용해 접근권한 통제를 테스트합니다.

핵심 감사위험: 권한 통제가 미흡하면 자동승인, 한도검증, 마감통제 등 ITAC가 정상 동작해도 우회 입력이나 사후 수정으로 재무제표 오류가 발생할 수 있습니다.

과정 구분: ITGC

통제 설계 실습

접근권한 통제의 설계가 직무분리, 최소권한, 적시 회수 원칙에 맞는지 검토합니다.

  • 사용자 생성, 권한 부여, 권한 변경, 퇴사자 회수 프로세스를 도식화합니다.
  • 전표 입력, 승인, 마스터 변경, 지급 실행 권한의 충돌 조합을 정의합니다.
  • 권한 요청서, 승인 증적, 시스템 반영일을 연결해 설계 적정성을 판단합니다.
  • 관리자 권한과 긴급권한 사용 기준을 별도 점검 항목으로 분리합니다.
  • 접근권한 통제 미비가 ITAC 신뢰성에 미치는 영향을 문서화합니다.

데이터 테스트 실습

권한 마스터와 접속 로그를 분석하여 예외 사용자를 추출합니다.

  • 사용자 마스터에서 퇴사자, 휴직자, 장기 미접속 계정을 식별합니다.
  • 권한 역할 테이블을 기준으로 SoD 충돌 계정을 추출합니다.
  • 권한 변경 로그와 승인 요청일을 비교해 사전승인 여부를 확인합니다.
  • 관리자 계정 사용 이력을 시간대, 기능, 변경 대상별로 분석합니다.
  • 예외 계정별 재무 프로세스 영향과 보완통제 필요성을 정리합니다.

감사 접근 비교 포인트

구분통제 설계 검토데이터 기반 운영평가
감사 초점통제 설계 실습에서 통제 설계와 책임 구조를 확인합니다.데이터 테스트 실습에서 데이터와 시스템 결과로 운영 여부를 입증합니다.
증거 방식정책서, 승인 문서, 인터뷰, 화면 증거를 활용합니다.원천 테이블, 로그, 변경 이력, 재수행 결과를 활용합니다.
결론 연결통제 미비의 원인과 보완통제 필요성을 정리합니다.예외 건수, 금액 영향, 반복 가능 감사절차를 산출합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실제 ERP와 감사조서 구조를 단순화하여 구성하고, 일부 오류를 의도적으로 반영합니다.

  • USER_MASTER: user_id, employee_id, status, department, last_login
  • ROLE_ASSIGNMENT: user_id, role_id, assigned_date, approved_by
  • ACCESS_LOG: user_id, action_type, object_name, timestamp

교육 진행 흐름

  1. 통제 이해: 업무 프로세스와 시스템 흐름을 읽고 통제 목적을 표시합니다.
  2. 위험 식별: 오류가 발생할 수 있는 입력, 처리, 출력, 변경 지점을 정리합니다.
  3. 증거 설계: 필요한 정책서, 화면, 로그, 테이블, 승인 증적을 정의합니다.
  4. 테스트 수행: 설계평가와 운영평가 절차를 수행하고 예외를 분류합니다.
  5. 결론 작성: 재무제표 영향, 통제 영향, 개선권고를 감사조서 문구로 작성합니다.
