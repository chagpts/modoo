05-10. ITAC 감사보고 정리

테스트 결과를 감사 발견사항, 영향도, 개선권고로 정리합니다.

실습 시나리오

접근권한, 변경관리, 인터페이스, 자동계산, 설정값 테스트에서 여러 예외가 발견되었습니다. 학습자는 발견사항을 중복 없이 통합하고 경영진 보고용 문구로 정리합니다.

핵심 감사위험: 개별 예외를 단순 나열하면 재무제표 영향, 통제 중요도, 개선 우선순위가 불명확해져 감사 결론과 후속조치가 약해질 수 있습니다.

과정 구분: ITAC

발견사항 정리 실습

ITAC 테스트 결과를 통제 목적, 원인, 영향, 개선안 중심으로 구조화합니다.

  • 예외를 설계 미비, 운영 미비, 데이터 오류, 증거 부족으로 분류합니다.
  • 동일 원인에서 발생한 예외를 하나의 발견사항으로 통합합니다.
  • 재무제표 영향, 업무 영향, ITGC 의존성 영향을 구분합니다.
  • 발견사항별 심각도와 개선 우선순위를 산정합니다.
  • 경영진 답변 요청 문구와 후속조치 기준을 작성합니다.

보고서 작성 실습

감사조서 결론을 경영진 보고서와 개선 로드맵으로 변환합니다.

  • 테스트 범위, 모집단, 절차, 결과를 요약 문단으로 작성합니다.
  • 예외 리스트를 핵심 발견사항 표로 재구성합니다.
  • 개선권고를 단기 조치와 구조적 개선으로 구분합니다.
  • 재테스트 일정과 책임부서를 후속조치 표에 반영합니다.
  • ITAC 감사보고의 최종 결론과 제한사항을 명확히 작성합니다.

감사 접근 비교 포인트

구분통제 설계 검토데이터 기반 운영평가
감사 초점발견사항 정리 실습에서 통제 설계와 책임 구조를 확인합니다.보고서 작성 실습에서 데이터와 시스템 결과로 운영 여부를 입증합니다.
증거 방식정책서, 승인 문서, 인터뷰, 화면 증거를 활용합니다.원천 테이블, 로그, 변경 이력, 재수행 결과를 활용합니다.
결론 연결통제 미비의 원인과 보완통제 필요성을 정리합니다.예외 건수, 금액 영향, 반복 가능 감사절차를 산출합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실제 ERP와 감사조서 구조를 단순화하여 구성하고, 일부 오류를 의도적으로 반영합니다.

  • ITAC_EXCEPTION: control_id, exception_id, exception_type, root_cause, impact_amount
  • MANAGEMENT_RESPONSE: finding_id, action_plan, owner, target_date
  • FOLLOW_UP: finding_id, status, retest_result, closed_date

교육 진행 흐름

  1. 통제 이해: 업무 프로세스와 시스템 흐름을 읽고 통제 목적을 표시합니다.
  2. 위험 식별: 오류가 발생할 수 있는 입력, 처리, 출력, 변경 지점을 정리합니다.
  3. 증거 설계: 필요한 정책서, 화면, 로그, 테이블, 승인 증적을 정의합니다.
  4. 테스트 수행: 설계평가와 운영평가 절차를 수행하고 예외를 분류합니다.
  5. 결론 작성: 재무제표 영향, 통제 영향, 개선권고를 감사조서 문구로 작성합니다.
