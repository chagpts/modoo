05-09. 통제증거 수집 자동화

반복되는 ITAC 감사증거를 표준화하고 자동 수집합니다.

실습 시나리오

감사팀은 매월 ITAC 증거로 스크린샷, 로그 추출본, 설정값 내역, 대사표를 요청하고 있습니다. 학습자는 수작업 증거 수집을 데이터 기반 패키지로 표준화합니다.

핵심 감사위험: 증거 수집이 수작업에 의존하면 누락, 기간 오류, 조작 가능성, 재현성 부족 문제가 발생하여 감사증거 신뢰성이 떨어질 수 있습니다.

과정 구분: ITAC

증거 요건 정의 실습

감사목적별로 필요한 증거의 원천, 기간, 형식, 보관 기준을 정의합니다.

  • 통제별 필수 증거와 선택 증거를 구분합니다.
  • 스크린샷 증거와 데이터 추출 증거의 장단점을 비교합니다.
  • 증거 기준일, 추출자, 추출 시간, 필터 조건을 메타데이터로 정의합니다.
  • 감사인이 재수행 가능한 형태의 원천 데이터 보관 기준을 수립합니다.
  • 증거 패키지의 무결성 확인 방법을 문서화합니다.

자동 수집 설계 실습

반복 증거를 쿼리, 로그, 파일명 규칙으로 표준화합니다.

  • 통제별 증거 추출 쿼리와 파일 템플릿을 설계합니다.
  • 추출 결과에 건수, 합계, 해시값, 생성일시를 자동 부여합니다.
  • 증거 파일명에 통제ID, 기간, 시스템명, 버전을 포함합니다.
  • 전월 증거와 비교해 누락 파일과 비정상 변동을 탐지합니다.
  • 자동 수집 결과를 감사조서 색인과 연결합니다.

감사 접근 비교 포인트

구분통제 설계 검토데이터 기반 운영평가
감사 초점증거 요건 정의 실습에서 통제 설계와 책임 구조를 확인합니다.자동 수집 설계 실습에서 데이터와 시스템 결과로 운영 여부를 입증합니다.
증거 방식정책서, 승인 문서, 인터뷰, 화면 증거를 활용합니다.원천 테이블, 로그, 변경 이력, 재수행 결과를 활용합니다.
결론 연결통제 미비의 원인과 보완통제 필요성을 정리합니다.예외 건수, 금액 영향, 반복 가능 감사절차를 산출합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실제 ERP와 감사조서 구조를 단순화하여 구성하고, 일부 오류를 의도적으로 반영합니다.

  • EVIDENCE_REQUEST: control_id, evidence_type, period, owner, due_date
  • EVIDENCE_FILE: control_id, file_name, extracted_at, record_count, hash_value
  • EVIDENCE_CHECK: control_id, completeness_result, integrity_result, reviewer

교육 진행 흐름

  1. 통제 이해: 업무 프로세스와 시스템 흐름을 읽고 통제 목적을 표시합니다.
  2. 위험 식별: 오류가 발생할 수 있는 입력, 처리, 출력, 변경 지점을 정리합니다.
  3. 증거 설계: 필요한 정책서, 화면, 로그, 테이블, 승인 증적을 정의합니다.
  4. 테스트 수행: 설계평가와 운영평가 절차를 수행하고 예외를 분류합니다.
  5. 결론 작성: 재무제표 영향, 통제 영향, 개선권고를 감사조서 문구로 작성합니다.
