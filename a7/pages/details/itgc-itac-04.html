05-04. 배치잡 운영통제

정기 자동처리 작업의 성공 여부와 오류 재처리를 검증합니다.

실습 시나리오

월말 매출채권 연령분석과 감가상각 계산 배치가 야간에 수행되지만, 일부 실패 로그가 수동으로 재처리되었습니다. 학습자는 배치잡 운영통제와 결과 데이터의 완전성을 확인합니다.

핵심 감사위험: 배치잡 실패, 중복 실행, 순서 오류가 발생하면 자동계산 결과가 누락되거나 중복 반영되어 재무제표 금액이 왜곡될 수 있습니다.

과정 구분: ITAC

운영통제 설계 실습

배치 스케줄, 선후행 관계, 오류 알림, 재처리 승인 기준을 검토합니다.

  • 월말·일별·실시간 배치잡 목록을 업무 프로세스별로 분류합니다.
  • 배치잡별 입력 테이블, 출력 테이블, 실행 주기, 담당자를 문서화합니다.
  • 실패 시 알림, 원인 분석, 재처리 승인 절차가 정의되어 있는지 확인합니다.
  • 선행 작업 실패 시 후행 작업이 차단되는지 통제 설계를 평가합니다.
  • 수동 재처리와 강제 완료 처리의 승인 기준을 조서에 반영합니다.

로그 재수행 실습

배치 로그와 결과 테이블을 분석해 실패, 중복, 누락 실행을 식별합니다.

  • 배치 스케줄 목록과 실제 실행 로그를 대사하여 미실행 작업을 찾습니다.
  • 실패 후 재처리된 작업의 처리 시간, 담당자, 승인 증적을 확인합니다.
  • 동일 배치가 동일 기간에 중복 실행된 사례를 추출합니다.
  • 출력 테이블의 건수와 금액 합계가 원천 데이터와 일치하는지 검증합니다.
  • 배치 오류가 재무제표 계정에 미친 영향을 산정합니다.

감사 접근 비교 포인트

구분통제 설계 검토데이터 기반 운영평가
감사 초점운영통제 설계 실습에서 통제 설계와 책임 구조를 확인합니다.로그 재수행 실습에서 데이터와 시스템 결과로 운영 여부를 입증합니다.
증거 방식정책서, 승인 문서, 인터뷰, 화면 증거를 활용합니다.원천 테이블, 로그, 변경 이력, 재수행 결과를 활용합니다.
결론 연결통제 미비의 원인과 보완통제 필요성을 정리합니다.예외 건수, 금액 영향, 반복 가능 감사절차를 산출합니다.

실습 데이터 예시

교육에서는 다음과 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 실제 ERP와 감사조서 구조를 단순화하여 구성하고, 일부 오류를 의도적으로 반영합니다.

  • BATCH_SCHEDULE: job_id, job_name, frequency, dependency_job_id
  • BATCH_LOG: job_id, run_date, status, start_time, end_time, operator
  • BATCH_RESULT: job_id, period, record_count, total_amount

교육 진행 흐름

  1. 통제 이해: 업무 프로세스와 시스템 흐름을 읽고 통제 목적을 표시합니다.
  2. 위험 식별: 오류가 발생할 수 있는 입력, 처리, 출력, 변경 지점을 정리합니다.
  3. 증거 설계: 필요한 정책서, 화면, 로그, 테이블, 승인 증적을 정의합니다.
  4. 테스트 수행: 설계평가와 운영평가 절차를 수행하고 예외를 분류합니다.
  5. 결론 작성: 재무제표 영향, 통제 영향, 개선권고를 감사조서 문구로 작성합니다.
