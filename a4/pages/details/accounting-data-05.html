05. 전산감사 관점의 데이터 요청

회사가 주는 자료를 그대로 받는 방식에서 벗어나, 감사 목적에 맞는 데이터 요청서와 필드 정의서를 작성하는 실습입니다.

실습 시나리오

회사는 전표 내역 엑셀을 제공했지만 입력자, 승인자, 수정일시, 원천 문서번호 필드가 빠져 있습니다. 일반감사팀은 증빙 확인은 가능하지만 전산감사 절차를 수행하기에는 데이터가 부족합니다.

핵심 감사위험: 불완전한 데이터로 분석을 수행해 잘못된 결론을 내리거나, 회사가 편집한 2차 자료만 보고 원천 데이터 이상을 놓칠 수 있습니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 확인, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 감사인은 필요한 명세서 이름, 대상 기간, 계정 범위, 담당자를 회사에 요청합니다.
  • 받은 파일이 감사 목적에 충분한지 확인하고 누락 항목은 추가 요청합니다.
  • 자료 요청 이력과 회사 답변을 조서에 남겨 추후 리뷰에 대비합니다.
  • 수기로 받은 파일의 합계가 재무제표 또는 원장과 일치하는지 대사합니다.
  • 수강생은 일반감사 자료 요청 목록과 수령 현황표를 작성합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 바꾸어 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 전산감사용 데이터 요청서는 테이블명, 필드명, 데이터 타입, 추출 조건, 기준시각, 해시값까지 명시합니다.
  • 전표 데이터는 헤더와 라인을 분리해 요청하고, 사용자·권한·승인 로그는 별도 파일로 요청합니다.
  • 마스터 데이터는 거래 기간 말일 기준 스냅샷과 변경 이력을 함께 요청합니다.
  • 수령 데이터의 건수, 합계, 중복 키, NULL 비율, 필드 형식을 즉시 점검합니다.
  • 수강생은 IT부서에 전달 가능한 데이터 요청서와 수령 데이터 검수 체크리스트를 만듭니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
요청 방식일반감사는 계정 명세서와 증빙 중심으로 요청합니다.전산감사는 원천 테이블, 로그, 마스터, 변경 이력까지 구조적으로 요청합니다.
품질 확인합계와 주요 항목 누락 여부를 확인합니다.건수, 키 유일성, 데이터 타입, 추출 조건, 기준시각을 확인합니다.
감사 효과수령 자료로 표본 절차를 수행합니다.분석 가능한 데이터 환경을 만들어 반복 가능한 테스트를 수행합니다.

실습 데이터 예시

수업에서는 아래와 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 만들고, 일부 오류를 의도적으로 심어 비교 실습을 진행합니다.

  • DATA_REQUEST: table_name, field_name, description, format, extraction_condition
  • DATA_RECEIPT_LOG: file_name, received_at, record_count, hash_value, owner
  • QUALITY_CHECK: field_name, null_rate, duplicate_count, min_value, max_value

수업 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 만들고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 확인 결과와 데이터 분석 결과가 서로 맞는지 확인한 뒤 최종 발견사항을 정리합니다.
