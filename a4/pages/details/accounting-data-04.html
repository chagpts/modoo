04. 일반감사 조서 작성 방식

동일한 회계 이슈를 일반감사 조서로 작성할 때 필요한 절차, 증빙, 결론 문구를 실습하고 전산감사 산출물과 어떻게 연결되는지 비교합니다.

실습 시나리오

감사팀은 매출채권 대손충당금, 재고평가, 미지급비용 중 하나를 선택해 감사조서를 작성해야 합니다. 회사는 엑셀 명세서를 제공했지만 원천 데이터와의 연결성은 명확하지 않습니다.

핵심 감사위험: 담당자가 만든 엑셀 명세서가 원장과 불일치하거나, 계산식이 누락되었거나, 감사 결론이 증거에 비해 과도하게 작성될 수 있습니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 확인, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 조서의 목적, 위험, 경영진 주장, 수행절차, 발견사항, 결론 순서로 기본 틀을 만듭니다.
  • 회사 제공 명세서를 받아 원장 금액과 대사하고 차이를 설명받습니다.
  • 표본을 선정해 외부증빙 또는 내부승인 문서를 확인합니다.
  • 감사인은 수행한 절차와 확인한 증거만으로 결론을 작성하고, 미확인 사항은 제한사항으로 남깁니다.
  • 수강생은 완결성 있는 1페이지 감사조서를 작성하고 리뷰 코멘트에 답변합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 바꾸어 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 엑셀 명세서가 어떤 ERP 테이블에서 생성되었는지 데이터 출처를 추적합니다.
  • 엑셀 계산식, 숨김 행, 수기 입력 셀, 중복 키를 검사하여 명세서 자체의 신뢰성을 점검합니다.
  • 원장 전체 데이터와 명세서를 거래처코드·품목코드·계정코드 기준으로 매칭합니다.
  • 조서에 첨부할 데이터 검증 로그, 변환 절차, 예외 처리 기준을 문서화합니다.
  • 수강생은 일반감사 조서 뒤에 붙일 전산감사 보조 조서를 작성합니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
조서 관점일반감사 조서는 감사 판단과 증빙 확인의 흐름을 보여줍니다.전산감사 조서는 데이터가 완전하고 정확하게 만들어졌는지를 설명합니다.
검토 대상회사 명세서와 표본 증빙을 중심으로 봅니다.명세서 생성 원천, 계산 로직, 데이터 변환 과정을 함께 봅니다.
리뷰 포인트절차와 결론의 연결성이 중요합니다.데이터 추출 조건과 재현 가능성이 중요합니다.

실습 데이터 예시

수업에서는 아래와 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 만들고, 일부 오류를 의도적으로 심어 비교 실습을 진행합니다.

  • WORKPAPER_INDEX: risk, assertion, procedure, evidence, conclusion
  • EXCEL_CHECK: sheet_name, formula_cell, manual_input_cell, hidden_row_count
  • RECON_RESULT: source_amount, ledger_amount, difference, reason

수업 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 만들고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 확인 결과와 데이터 분석 결과가 서로 맞는지 확인한 뒤 최종 발견사항을 정리합니다.

수업 산출물

  • 리뷰 코멘트 답변표
  • 명세서 신뢰성 점검표
  • 전산감사 보조 조서
