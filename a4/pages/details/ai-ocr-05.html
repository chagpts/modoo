05. 전표 자동 생성 규칙

추출된 증빙 필드를 회계 계정과목, 부가세 코드, 거래처, 적요, 차변·대변 전표 초안으로 변환합니다.

실습 개요

룰 기반 엔진과 Gemma 추천 결과를 결합해 사람이 검토 가능한 전표 초안을 생성

이 페이지는 단순 OCR 데모가 아니라, 회계 증빙이 실제 전표로 이어지는 프로그램을 만든다는 전제로 구성했습니다. 교육생은 Python 기반 백엔드, 로컬 OCR 엔진, Gemma 로컬 AI 추론, 검증 화면, 회계 데이터베이스, 감사로그를 하나의 업무 시스템으로 연결합니다.

Gemma는 외부 API로 증빙을 보내지 않는 로컬 AI 구성의 핵심으로 사용합니다. 수업에서는 모델 자체를 맹신하지 않고, 룰 기반 검증·사람 승인·감사증적을 결합해 회계감사와 전산감사 모두에서 설명 가능한 결과를 만드는 것을 목표로 합니다.

업무 시나리오

  • AI가 필드를 추출해도 곧바로 회계처리가 되는 것은 아닙니다. 회계 계정과목, 부가세 코드, 비용부서, 프로젝트, 적요 규칙이 필요합니다.
  • 교육생은 룰 기반 전표 생성 엔진을 먼저 만들고, Gemma는 계정과목 추천과 적요 보완에 제한적으로 사용합니다.

실제 개발 실습 절차

  1. 거래처·품목·키워드 기반 계정 매핑표를 작성합니다. 예: 통신사 요금은 통신비, 택배사는 운반비, 클라우드 서비스는 지급수수료 또는 소프트웨어사용료 후보로 매핑합니다.
  2. 부가세 처리 규칙을 만듭니다. 세금계산서 과세 거래, 카드영수증 일반과세, 면세 거래, 접대비성 거래를 구분합니다.
  3. Gemma에는 계정과목을 단정하게 하지 않고 후보 3개, 판단근거, 추가 확인 질문을 생성하게 합니다. 최종 전표는 룰과 승인자가 확정합니다.
  4. 차변·대변 균형, 합계금액 일치, 필수 코스트센터 존재, 승인 완료 여부를 검사한 뒤 ERP 업로드 CSV를 생성합니다.

수업에서는 완성된 정답 프로그램을 복사하지 않고, 작은 기능 단위로 구현한 뒤 테스트 데이터를 통과시키는 방식으로 진행합니다. 예를 들어 OCR 결과가 비어 있는 경우, Gemma 응답이 JSON 형식을 지키지 않는 경우, 공급가액과 부가세 합계가 맞지 않는 경우를 일부러 만들어 방어 로직을 작성합니다.

Gemma 프롬프트·JSON 설계 예시

프롬프트는 회계 판단을 설명 가능하게 만들기 위해 출력 형식을 제한합니다. 아래 예시는 수업에서 사용하는 기본 구조입니다.

  • document_type: 세금계산서, 카드영수증, 현금영수증, 거래명세서 등 문서 유형
  • fields: 거래일자, 거래처명, 사업자번호, 공급가액, 부가세, 합계금액, 품목, 결제수단
  • evidence: 각 필드가 OCR 원문 어디에서 추출되었는지 설명하는 근거
  • confidence: 필드별 신뢰도와 전체 신뢰도
  • exceptions: 금액 불일치, 필수값 누락, 중복 의심, 사람이 확인해야 할 사유

중요한 원칙은 Gemma가 모르는 값을 추측하지 않게 하는 것입니다. 값이 없으면 null로 두고, 검증 화면에서 사람이 확인하도록 설계합니다. 이 원칙이 없으면 AI 자동화가 오히려 회계 오류를 조용히 만들어낼 수 있습니다.

  • 일반감사는 표본 전표의 계정과목과 증빙 성격을 검토합니다.
  • 전산감사는 계정 매핑표 변경권한, 룰 적용 일관성, AI 추천값과 최종 승인값의 차이를 분석합니다.
  • 전표 자동 생성은 편리하지만 승인 없는 ERP 반영을 막는 통제가 반드시 필요합니다.

테스트 데이터와 검증 기준

각 페이지에서는 정상 증빙만 사용하지 않습니다. 실제 운영에서 문제가 되는 데이터를 섞어 자동화 품질을 확인합니다.

  • 정상 세금계산서 20건, 정상 카드영수증 20건, 현금영수증 10건을 기본 모집단으로 준비합니다.
  • 흐릿한 이미지, 기울어진 이미지, 금액이 잘린 이미지, 사업자번호가 누락된 이미지, 합계금액이 OCR에서 잘못 읽힌 이미지를 오류 케이스로 넣습니다.
  • 동일 승인번호 또는 동일 파일 해시를 가진 중복 증빙을 넣어 중복 검출 로직을 확인합니다.
  • 검증 기준은 단순 성공 여부가 아니라 필드별 정확도, 예외 검출률, 승인 전 차단률, 사용자 수정률, 로그 완전성으로 평가합니다.

수업 진행 흐름

  1. 강사가 회계 업무 시나리오와 감사위험을 설명합니다.
  2. 교육생이 입력 데이터와 필요한 테이블을 직접 설계합니다.
  3. OCR 결과를 확인하고 Gemma에 전달할 프롬프트와 JSON 스키마를 작성합니다.
  4. AI 응답을 DB에 저장하고 검증 규칙을 통과하지 못한 건을 예외 큐로 보냅니다.
  5. 일반 회계감사 방식으로 표본을 확인한 뒤, 전산감사 방식으로 전체 모집단과 로그를 분석합니다.
  6. 마지막에는 프로그램 기능, 통제 설계, 테스트 결과를 하나의 조서형 산출물로 제출합니다.

최종 산출물

  • 업무흐름도와 시스템 구성도
  • 입력 데이터 명세서와 DB 테이블 초안
  • Gemma 프롬프트 버전과 JSON 응답 예시
  • OCR·AI 추출 결과 검증표
  • 예외 목록, 처리 결과, 개선권고안
  • 일반 회계감사 절차와 전산감사 절차 비교 조서

이 산출물은 단순 수업 과제가 아니라 포트폴리오로 사용할 수 있게 구성합니다. 지원자는 회계 업무를 이해하고, 로컬 AI를 활용한 자동화 흐름을 만들 수 있으며, 동시에 감사 가능한 통제 설계를 설명할 수 있다는 점을 보여줄 수 있습니다.
