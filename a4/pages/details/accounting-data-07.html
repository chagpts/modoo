07. 이상거래 탐색 기본 로직

감사인이 경험적으로 의심하는 거래를 데이터 규칙으로 바꿔 이상거래 탐색 로직을 설계합니다.

실습 시나리오

회사에서 기말 직전 대량 전표, 동일 금액 반복 지급, 퇴사자 계정 입력, 승인자와 입력자가 같은 전표가 발견될 수 있다는 제보가 있었습니다.

핵심 감사위험: 부정 전표, 승인 우회, 권한 남용, 비용 조작, 마감 조정 거래 은폐 가능성입니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 확인, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 제보 내용을 토대로 어떤 경영진 주장과 계정에 영향을 주는지 정리합니다.
  • 의심 거래 유형별로 필요한 증빙과 담당자 인터뷰 질문을 작성합니다.
  • 금액이 큰 거래, 승인흐름이 이상한 거래, 설명이 부족한 거래를 선정해 증빙을 확인합니다.
  • 확인 결과를 부정 징후, 오류 가능성, 정상 거래로 구분합니다.
  • 수강생은 이상거래 확인 인터뷰 메모와 후속 절차 계획을 작성합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 바꾸어 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 이상거래 규칙을 명확한 조건으로 바꿉니다. 예: 입력자=승인자, posting_date가 휴일, amount가 1,000,000 단위로 끝남.
  • 사용자 마스터와 인사 데이터를 연결하여 퇴사일 이후 입력·승인 내역을 탐색합니다.
  • 동일 거래처·동일 금액·짧은 기간 반복 거래를 그룹핑합니다.
  • 규칙별 적중 건수와 실제 오류율을 비교해 탐지 로직을 개선합니다.
  • 수강생은 이상거래 탐색 규칙 목록과 테스트 결과를 작성합니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
의심의 출발점일반감사는 인터뷰, 분석적 절차, 감사인 경험에서 출발합니다.전산감사는 의심을 조건식과 조인 로직으로 변환합니다.
결과 해석증빙과 설명을 통해 정상 여부를 판단합니다.규칙 적중은 의심 신호일 뿐이며 일반감사 확인으로 결론을 보강합니다.
개선 방식추가 인터뷰와 표본 확대를 수행합니다.오탐·미탐을 줄이기 위해 조건과 점수화를 조정합니다.

실습 데이터 예시

수업에서는 아래와 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 만들고, 일부 오류를 의도적으로 심어 비교 실습을 진행합니다.

  • USER_MASTER: user_id, employee_id, department, active_flag, terminated_date
  • APPROVAL_LOG: document_id, input_user, approval_user, approval_time
  • EXCEPTION_RULE: rule_id, rule_name, condition, severity

수업 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 만들고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 확인 결과와 데이터 분석 결과가 서로 맞는지 확인한 뒤 최종 발견사항을 정리합니다.

수업 산출물

  • 이상거래 유형별 리스크 매트릭스
  • 인터뷰 질문지
  • 탐색 규칙 설계서
  • 예외 적중 결과표
