자동계산 통제 테스트

세금, 할인, 이자, 감가상각, 환산손익 등 자동계산 ITAC를 감사인이 직접 재수행하는 실습입니다.

04-06 실습 개요

ERP가 매출세액, 매출할인, 연체이자, 외화환산손익을 자동 계산합니다. 감사인은 산식 정의서와 설정값, 샘플 거래 데이터를 이용해 시스템 계산값을 독립적으로 재계산하고 차이를 분석합니다.

이 페이지는 CISA식 정보시스템 감사 사고방식에 맞춰 감사계획, 시스템·데이터 흐름 이해, 핵심통제 식별, 테스트 수행, 예외 평가, 보고서 작성 순서로 구성했습니다. 단순 개념 설명이 아니라 수강생이 실제 감사 조서에 옮길 수 있는 절차와 산출물 중심으로 진행합니다.

감사위험과 ITAC 초점

자동계산 통제는 오류가 반복적으로 확산되는 특성이 있습니다. 산식 하나가 잘못되면 모든 거래가 동일하게 왜곡될 수 있으므로, 설계 이해와 재수행 테스트가 핵심입니다.

  • 중점 ITAC: 부가세 자동계산, 할인율 한도, 이자계산 산식, 환율 적용, 감가상각 자동계산
  • 관련 재무제표 주장: 완전성, 정확성, 발생사실, 기간귀속, 분류, 승인
  • 감사인 판단 포인트: 통제가 자동으로 작동하는지, 사용자가 우회할 수 있는지, 예외가 검토되는지, 증거가 재현 가능한지 확인합니다.

일반 ITGC 감사 접근

  1. 통제환경과 업무 프로세스를 이해하고 감사 범위를 확정합니다.
  2. 권한관리, 변경관리, 운영관리, 배치관리 등 기반통제 설계 문서를 요청합니다.
  3. 표본을 선정하여 승인서, 로그, 티켓, 검토증거가 존재하는지 확인합니다.
  4. 통제 미비가 자동통제 신뢰성에 미치는 영향을 평가합니다.
  5. 문서상 통제와 실제 시스템 운영이 다른 부분을 발견사항으로 정리합니다.

ITAC 중심 전산감사 접근

  1. 업무거래가 시스템에서 입력·처리·출력되는 흐름을 데이터 단위로 추적합니다.
  2. 자동계산, 자동승인, 입력검증, 인터페이스, 예외리포트 통제를 식별합니다.
  3. 모집단 데이터를 추출하고 통제 조건식을 감사인이 독립적으로 재수행합니다.
  4. 시스템 결과와 감사인 재수행 결과의 차이를 예외로 분류합니다.
  5. ITGC 미비와 ITAC 예외를 결합하여 통제 의존 가능 여부를 결론냅니다.

필요 데이터와 증빙 목록

수업에서는 아래 증거를 요청목록 형태로 작성한 뒤, 각 증거의 원천 시스템과 추출 조건을 함께 기록합니다. 증거가 화면 캡처인지, 원천 로그인지, 담당자 가공 파일인지에 따라 신뢰수준을 구분합니다.

  • 산식 정의서와 프로그램 명세서
  • 세율·환율·할인율 마스터
  • 샘플 거래 원장
  • 시스템 계산 결과 테이블
  • 감사인 재계산 워크시트

실제 감사 실습 절차

  1. 산식 정의서의 입력값, 처리조건, 반올림 기준, 예외조건을 표로 정리한다.
  2. 고위험 표본과 무작위 표본을 선정하여 감사인 재계산값과 시스템값을 비교한다.
  3. 마스터 값 변경일과 거래일을 비교해 거래 시점의 정확한 설정값이 적용되었는지 확인한다.
  4. 허용오차를 초과한 차이는 산식오류, 마스터오류, 수기수정, 반올림차이로 원인을 분류한다.
  5. 예외가 발견되면 업무담당자 인터뷰로 원인을 확인하되, 인터뷰 내용만으로 종결하지 않고 원천 데이터와 승인 증거를 다시 대사합니다.
  6. 테스트 결과를 조서에 남길 때는 모집단 정의, 표본선정 기준, 테스트 조건, 예외 판단근거, 결론을 분리하여 작성합니다.

통제기술서 예시

시스템은 거래일 기준 유효 세율과 환율을 자동 적용하고, 계산결과를 사용자가 직접 수정할 수 없으며 수정이 필요한 경우 승인 워크플로우를 생성한다.

수강생은 이 문장을 그대로 외우는 것이 아니라, 통제 소유자, 통제 빈도, 사용 시스템, 입력 데이터, 처리 로직, 출력 증거, 예외처리 절차가 모두 포함되도록 자기 조서 문장으로 다시 작성합니다.

ITGC vs ITAC 비교 조서

구분ITGC 관점ITAC 관점
감사목적ITGC가 시스템 통제환경의 신뢰성을 뒷받침하는지 확인한다.ITAC가 개별 거래의 완전성·정확성·타당성을 자동으로 보장하는지 확인한다.
주요증거권한승인, 변경관리 티켓, 배포로그, 운영로그, 백업·모니터링 기록입력검증 결과, 자동계산 산식, 승인워크플로우 로그, 예외리포트, 인터페이스 대사표
테스트방법표본 기반 문서점검과 로그 확인을 수행하고, 통제 운영기간의 일관성을 확인한다.모집단 데이터 재수행, 조건식 검증, 예외 추출, 시스템 결과와 감사인 계산값 비교를 수행한다.
결론영향ITGC 미비가 있으면 ITAC 증거의 신뢰성이 낮아져 추가 실증절차가 필요할 수 있다.ITAC 미비가 있으면 특정 계정과목 또는 거래흐름의 왜곡 위험이 증가한다.

샘플 데이터 필드

테이블/파일주요 필드감사 활용 방법
USER_ROLEuser_id, role_id, granted_date, revoked_date, approver_id권한 승인 적정성, 직무분리 충돌, 퇴사자 권한 잔존 여부를 확인합니다.
CHANGE_LOGchange_id, object_name, before_value, after_value, developer_id, deploy_time자동통제 로직 또는 설정값 변경이 승인된 절차를 거쳤는지 확인합니다.
TXN_MASTERtxn_id, txn_date, amount, status, created_by, approved_by거래 입력부터 승인, 전표 생성까지 통제 조건이 충족되었는지 추적합니다.
EXCEPTION_LOGexception_id, rule_id, reason_code, resolved_by, resolved_time자동통제가 탐지한 예외가 적시에 검토되고 승인되었는지 확인합니다.

예외사항 판단 예시

외화매출 환산 시 거래일 환율이 아닌 배치 실행일 환율이 적용된 거래가 발견되었습니다. 환산손익 자동계산 로직의 설계 오류 가능성이 있어 전체 모집단 재계산이 필요합니다.

조서 결론은 “문제가 있다”가 아니라 “어떤 통제가, 어느 기간에, 어떤 모집단에서, 어떤 재무제표 주장에 영향을 주며, 감사인이 어떤 추가절차를 수행해야 하는지”까지 연결해야 합니다.
