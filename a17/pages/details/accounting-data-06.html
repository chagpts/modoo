06. 샘플링과 전체 모집단 분석 비교

표본감사의 논리와 전체 모집단 분석의 장단점을 같은 거래 데이터로 비교해 검토합니다.

실습 시나리오

매출 거래가 50,000건 존재합니다. 일반감사팀은 중요성 기준에 따라 표본을 선정하려 하고, 전산감사팀은 전체 거래를 분석해 예외 패턴을 우선 식별하고자 합니다.

핵심 감사위험: 표본에 포함되지 않은 거래에서 중요한 오류가 발생하거나, 전체 분석 결과를 해석하지 못해 불필요한 예외만 많이 구축하는 위험입니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 검토, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 모집단을 정의하고 표본추출 단위, 표본 크기, 선정 기준을 문서화합니다.
  • 금액기준 표본, 무작위 표본, 특정위험 표본을 구분해 선수립합니다.
  • 선정 표본에 대해 계약서, 출고증, 세금계산서, 입금내역을 검토합니다.
  • 표본 오류가 발견되면 오류율, 금액왜곡, 추가 표본 필요성을 검토합니다.
  • 학습자는 표본 선정 근거와 표본 테스트 결과표를 작성합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 치환하여 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 전체 매출 모집단에 대해 금액, 일자, 거래처, 입력자, 승인자 기준으로 분포를 분석합니다.
  • Benford 성향, 라운드 금액, 마감일 집중, 동일 금액 반복, 야간·휴일 입력을 예외 조건으로 설수립합니다.
  • 예외 거래를 위험 점수로 정렬하고 일반감사 표본과 겹치는지 검토합니다.
  • 전체 분석 결과가 모두 오류를 의미하지 않으므로 후속 검토 규칙을 설계합니다.
  • 학습자는 전체 모집단 예외 분석 대시보드용 표를 작성합니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
선정 논리일반감사는 대표성 또는 중요성에 따라 일부 거래를 선택합니다.전산감사는 전체를 훑은 뒤 위험도가 높은 거래를 우선 검토합니다.
장점증빙 검토가 깊고 감사 판단을 명확히 남기기 좋습니다.누락 없는 범위 검토과 반복 수행에 강합니다.
주의점표본 외 오류를 식별하지 못할 수 있습니다.예외가 많아질수록 후속 판단 기준이 필요합니다.

실습 데이터 예시

교육에서는 다음과 등의 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 작성하고, 일부 오류를 의도적으로 반영하여 비교 실습을 진행합니다.

  • POPULATION: transaction_id, amount, posting_date, customer_id, user_id
  • SAMPLE_SELECTION: method, sample_id, reason, tested_result
  • EXCEPTION_SCORE: transaction_id, rule_hit_count, risk_score, follow_up_result

교육 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 작성하고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 검토 결과와 데이터 분석 결과가 서로 맞는지 검토한 뒤 최종 발견사항을 정리합니다.

교육 산출물

  • 전체 모집단 분석 규칙표
  • 예외 거래 위험 점수표
