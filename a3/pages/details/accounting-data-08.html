08. 감사증거와 시스템 데이터 연결

종이·PDF 증빙과 ERP 원천 데이터를 연결하여 감사증거의 신뢰성과 충분성을 판단하는 실습입니다.

실습 시나리오

회사 담당자는 세금계산서 PDF와 거래명세서를 제출했지만, 해당 문서가 실제 ERP 전표와 연결되어 있는지 확인되지 않습니다. 일부 PDF는 파일명만 있고 문서번호가 누락되어 있습니다.

핵심 감사위험: 증빙 재사용, 전표와 무관한 증빙 첨부, 사후 생성된 증빙, 문서번호 누락으로 인한 추적 불가능성입니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 확인, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 감사인은 증빙 원본성, 발행일, 거래처, 금액, 품목, 승인 흔적을 확인합니다.
  • 전표번호와 증빙 문서번호가 일치하는지 수기로 대조합니다.
  • 외부증빙은 필요 시 거래처 확인 또는 전자세금계산서 조회 결과로 보강합니다.
  • 증빙이 충분하지 않으면 대체절차와 제한사항을 조서에 남깁니다.
  • 수강생은 증빙 충분성 판단표를 작성합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 바꾸어 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 문서관리시스템의 첨부파일 메타데이터와 ERP 전표 데이터를 연결합니다.
  • 파일 생성일, 업로드일, 업로드 사용자, 문서번호, 해시값을 확인해 사후 변경 가능성을 점검합니다.
  • 동일 파일 해시가 여러 전표에 첨부된 건을 찾아 증빙 재사용 가능성을 확인합니다.
  • OCR 결과의 공급자등록번호, 금액, 일자를 전표 필드와 비교합니다.
  • 수강생은 증빙-전표 매칭 결과와 불일치 리스트를 작성합니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
증거 신뢰성일반감사는 문서 내용과 외부성에 집중합니다.전산감사는 문서 메타데이터와 시스템 연결성을 함께 봅니다.
추적성전표번호와 증빙번호를 수기로 연결합니다.키 값, 해시, 업로드 로그로 자동 연결합니다.
불일치 처리담당자 설명과 대체증빙을 확보합니다.불일치 유형을 분류하고 재발 방지 통제까지 연결합니다.

실습 데이터 예시

수업에서는 아래와 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 만들고, 일부 오류를 의도적으로 심어 비교 실습을 진행합니다.

  • DOCUMENT_META: file_id, file_name, hash_value, uploaded_at, uploaded_by
  • ATTACHMENT_LINK: journal_id, file_id, document_type
  • OCR_RESULT: file_id, vendor_reg_no, invoice_date, total_amount

수업 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 만들고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 확인 결과와 데이터 분석 결과가 서로 맞는지 확인한 뒤 최종 발견사항을 정리합니다.

수업 산출물

  • 증빙 충분성 판단표
  • 전표-증빙 매칭표
  • 파일 메타데이터 점검표
  • 불일치 후속 확인 목록
