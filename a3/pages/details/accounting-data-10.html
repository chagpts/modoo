10. 미니 케이스 리뷰

회계 데이터 이해 과정에서 배운 내용을 하나의 미니 감사 케이스로 통합합니다. 일반감사와 전산감사의 역할 분담, 산출물 연결, 최종 결론 작성까지 실습합니다.

실습 시나리오

가상의 제조업 회사에서 매출 급증, 재고평가 변동, 비용 계정 오분류, 마감 이후 전표 입력이 동시에 발견되었습니다. 수강생은 감사팀과 전산감사팀으로 역할을 나누어 케이스를 수행합니다.

핵심 감사위험: 복수 계정에서 발생한 오류가 서로 연결되어 재무제표 전체 왜곡으로 확대될 가능성입니다. 또한 전산 통제 미흡으로 동일 문제가 반복될 수 있습니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 확인, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 감사팀은 중요한 계정과 경영진 주장을 식별하고 일반감사 프로그램을 작성합니다.
  • 매출, 재고, 비용, 마감 전표 중 우선순위를 정하고 표본 확인 절차를 수행합니다.
  • 회사 담당자 인터뷰를 통해 거래 배경, 승인 절차, 수정분개 사유를 확인합니다.
  • 발견사항을 재무제표 영향, 내부통제 영향, 추가 감사 필요성으로 나누어 정리합니다.
  • 수강생은 최종 감사 메모와 조서 색인을 작성합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 바꾸어 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 전산감사팀은 원장, 전표, 마스터, 로그, 증빙 메타데이터를 받아 데이터 완전성부터 확인합니다.
  • 이전 9개 수업의 규칙을 조합해 컷오프, 오분류, 중복, 권한, 증빙 불일치 예외를 추출합니다.
  • 예외 리스트를 위험 점수로 정렬하고 일반감사팀이 확인할 표본으로 넘깁니다.
  • 확인 결과를 다시 규칙에 반영해 실제 오류와 정상 예외를 구분합니다.
  • 수강생은 전산감사 결과 요약 대시보드용 표와 개선 권고안을 작성합니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
역할 분담일반감사팀은 회계적 판단과 증빙 확인을 담당합니다.전산감사팀은 전체 데이터 분석과 예외 선별을 담당합니다.
통합 방식표본 조서와 인터뷰 메모로 결론을 보강합니다.데이터 계보, 규칙 적중 결과, 로그 분석으로 결론을 보강합니다.
최종 산출물감사 결론과 수정권고가 중심입니다.반복 가능한 감사 프로그램과 통제 개선안까지 포함합니다.

실습 데이터 예시

수업에서는 아래와 같은 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 만들고, 일부 오류를 의도적으로 심어 비교 실습을 진행합니다.

  • CASE_LEDGER: account_code, period, amount, journal_id, description
  • CASE_EXCEPTION: journal_id, exception_type, risk_score, assigned_team
  • CASE_CONCLUSION: issue, financial_impact, control_impact, recommendation

수업 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 만들고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 확인 결과와 데이터 분석 결과가 서로 맞는지 확인한 뒤 최종 발견사항을 정리합니다.
