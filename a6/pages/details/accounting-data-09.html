09. 회계감사 시험 예제 전산화

회계감사 시험형 문제를 실제 전산감사 절차로 바꾸는 연습입니다. 서술형 답안을 데이터 요청, 테스트 로직, 조서 산출물로 전환합니다.

실습 시나리오

시험 문제에서는 매출채권 검토, 재고 실사, 비용 컷오프, 권한 분리 같은 주제가 서술형으로 제시됩니다. 실무에서는 이 내용을 데이터 기반 감사 프로그램으로 바꿔야 합니다.

핵심 감사위험: 이론적 답안은 알고 있지만 실제 데이터 필드, 테스트 조건, 산출물로 전환하지 못해 현장 적용이 어려운 위험입니다.

일반 회계감사 실습

감사인이 실제 조서를 작성한다는 전제로 증빙 검토, 인터뷰, 표본 검토, 결론 작성까지 수행합니다.

  • 시험 예제의 조건에서 경영진 주장, 감사위험, 필요한 감사절차를 표시합니다.
  • 일반감사 답안 형식으로 검토, 관찰, 질문, 재계산, 분석적 절차를 정리합니다.
  • 각 절차별 필요한 증빙과 조서 제목을 붙입니다.
  • 감사 결론을 작성하기 위해 어떤 오류가 발견되면 어떤 후속절차가 필요한지 작성합니다.
  • 학습자는 시험형 답안을 일반감사 조서 목차로 전환합니다.

전산감사 실습

같은 감사위험을 데이터 관점으로 치환하여 원천 테이블, 로그, 마스터, 예외 조건을 활용합니다.

  • 시험 예제의 감사절차를 데이터 필드와 조건식으로 번역합니다.
  • 예를 들어 매출 컷오프 문제는 ship_date, invoice_date, posting_date, period 필드 비교로 전환합니다.
  • 권한 분리 문제는 사용자, 역할, 승인 로그, 전표 로그의 조인으로 전환합니다.
  • 각 테스트마다 데이터 요청 항목, 예외 조건, 결과 컬럼, 후속 검토 절차를 정의합니다.
  • 학습자는 시험 예제 3개를 전산감사 테스트 설계서로 바꿉니다.

일반감사 vs 전산감사 비교 포인트

구분일반 회계감사전산감사
학습 방식일반감사는 이론과 조서 문구를 우선 익힙니다.전산감사는 같은 이론을 데이터 구조와 테스트 조건으로 구현합니다.
답안 형태위험, 절차, 증거, 결론의 서술형 답안입니다.요청 데이터, 쿼리 조건, 예외 리스트, 후속 절차의 설계서입니다.
실무 연결감사 기준을 이해하는 데 강점이 있습니다.현장 자동화와 반복 테스트로 연결하기 쉽습니다.

실습 데이터 예시

교육에서는 다음과 등의 필드를 가진 샘플 CSV 또는 엑셀 파일을 사용합니다. 데이터는 회사 실무 자료와 유사한 구조로 작성하고, 일부 오류를 의도적으로 반영하여 비교 실습을 진행합니다.

  • EXAM_CASE: topic, assertion, risk, general_procedure
  • TEST_DESIGN: data_field, condition, exception_output, follow_up
  • QUERY_RESULT: case_id, exception_count, sample_needed, conclusion

교육 진행 흐름

  1. 이슈 읽기: 회계감사 시험형 문제 또는 현업 시나리오를 읽고 감사위험을 표시합니다.
  2. 일반감사 설계: 필요한 증빙, 표본 선정 기준, 인터뷰 질문, 조서 결론 문구를 작성합니다.
  3. 데이터 설계: 필요한 테이블과 필드를 정의하고, 누락되면 어떤 분석이 불가능한지 설명합니다.
  4. 예외 추출: 전체 모집단에서 규칙 기반 예외를 작성하고 일반감사 표본과 비교합니다.
  5. 통합 결론: 증빙 검토 결과와 데이터 분석 결과가 서로 맞는지 검토한 뒤 최종 발견사항을 정리합니다.
